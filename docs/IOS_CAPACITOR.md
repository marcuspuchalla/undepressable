# iOS build & distribution (Capacitor)

Undepressable runs on iPhone/iPad as a **Capacitor** app — the same Vue build
inside a `WKWebView`, bundled offline. This is the path to a real installable
`.ipa`; the PWA (Add to Home Screen) remains the zero-friction fallback.

- App id: `app.undepressable`
- Native project: [`../ios/`](../ios) (committed; generated by `npx cap add ios`)
- Camera/mic usage strings live in [`../ios/App/App/Info.plist`](../ios/App/App/Info.plist).

Reminder: iOS distribution is genuinely harder than Android — Apple gates both
the App Store and sideloading. See [`FEASIBILITY.md`](FEASIBILITY.md) and
[`../MOBILE_DISTRIBUTION.md`](../MOBILE_DISTRIBUTION.md) for the trade-offs.

## Prerequisites

| Tool | Notes |
|------|-------|
| macOS + Xcode 15+ | required to build iOS at all |
| CocoaPods | `pod install` runs automatically on `cap add`/`cap sync` |
| An Apple ID | free tier signs 7-day builds; a paid Developer account signs 1-year / App Store builds |

## Sync and open

```bash
npm run build && npx cap sync ios     # copy dist/ into the iOS project
npx cap open ios                      # open App.xcworkspace in Xcode
```

Always open **`App.xcworkspace`**, not the `.xcodeproj` (CocoaPods).

## Camera / microphone

The stream uses `getUserMedia` in the WebView. On iOS this needs two things,
both already in place:

- `NSCameraUsageDescription` + `NSMicrophoneUsageDescription` in Info.plist
  (Apple rejects the build without them).
- Inline playback — Capacitor's `WKWebView` allows it by default.

On first stream, iOS shows the system camera/mic prompt. On-device verification
is owed — see [`TEST_PLAN.md`](TEST_PLAN.md) Scenario 1.

## Build & run

### On the simulator (no signing)

```bash
xcodebuild -workspace ios/App/App.xcworkspace -scheme App \
  -sdk iphonesimulator -configuration Debug \
  CODE_SIGNING_ALLOWED=NO build
```

Note: the simulator has no camera, so streaming can't be exercised there — use a
real device for the camera path.

### On a real device (needs signing)

1. In Xcode → target **App** → **Signing & Capabilities**, pick your Team.
   Xcode auto-manages a provisioning profile.
2. Set a unique bundle id if `app.undepressable` is taken on your account.
3. Select your device and press Run.

With a free Apple ID the app runs for 7 days, then must be re-signed (this is
Apple's limit, not the app's).

## Distribution options

| Channel | Who signs | Lifetime | Notes |
|---------|-----------|----------|-------|
| **PWA** (Add to Home Screen) | nobody | permanent | No Xcode, no account — the resilient default for iOS |
| **TestFlight** | you (paid account) | 90 days/build | Up to 10k testers; Apple reviews the first build |
| **App Store** | you (paid account) | permanent | Subject to review; a P2P/streaming app may draw scrutiny (Guideline 4.2 / UGC rules) |
| **AltStore / Sideloadly** | user's Apple ID | 7 days | No review; user re-signs weekly |

### Making an .ipa (paid account)

```bash
# Archive, then export with your export options plist
xcodebuild -workspace ios/App/App.xcworkspace -scheme App \
  -configuration Release -archivePath build/App.xcarchive archive
xcodebuild -exportArchive -archivePath build/App.xcarchive \
  -exportOptionsPlist ExportOptions.plist -exportPath build/ipa
```

`ExportOptions.plist` selects the method (`app-store`, `ad-hoc`, or
`development`) and your team id. Keep signing assets out of the repo.

## Versioning

Bump the version in Xcode (target → General → **Version** /
`MARKETING_VERSION`) and **Build** (`CURRENT_PROJECT_VERSION`) for each release.
Keep them in step with `package.json`, `capacitor.config.ts`, and the Android
`versionName`.

## Why the PWA still matters on iOS

Because every native channel above has a catch (review, weekly re-signing, a
paid account), the installable PWA is the one iOS path with no gatekeeper. Keep
it working — it's the fallback when the native app can't reach someone.
