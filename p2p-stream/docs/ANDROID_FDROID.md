# Android build & F-Droid release

Undepressable ships to Android as a **Capacitor** app: the same Vue web build,
bundled inside a native WebView APK. No remote server, no Google Play Services,
no proprietary SDKs — which is exactly what F-Droid wants.

- App id: `app.undepressable`
- Native project: [`../android/`](../android) (committed; generated by `npx cap add android`)
- Config: [`../capacitor.config.ts`](../capacitor.config.ts) — `webDir: dist`, assets bundled, offline-capable.

## Prerequisites

| Tool | Version | Notes |
|------|---------|-------|
| Node | 20+ | to build the web app |
| JDK | 17 | Gradle/AGP 8 needs 17 |
| Android SDK | platform 34, build-tools 34 | `ANDROID_HOME` must be set |

Nothing Google-proprietary is required. The APK holds only three permissions:
`INTERNET`, `CAMERA`, `RECORD_AUDIO` (camera + mic are for WebRTC capture).

## The one-command sync

Whenever the web app changes, rebuild it and copy it into the native project:

```bash
npm run build          # produces dist/
npx cap sync android   # copies dist/ into android/ and updates native deps
```

`cap sync` is also what a reproducible F-Droid build runs before Gradle (see below).

## Build a debug APK (for testing)

```bash
npm run build && npx cap sync android
cd android
./gradlew assembleDebug
# → android/app/build/outputs/apk/debug/app-debug.apk  (~4.4 MB)
```

Install it on a plugged-in phone (USB debugging on):

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

### Camera / microphone in the WebView

The stream is captured with `getUserMedia` **inside** the WebView. Android's
WebView only hands that to the page if the app itself holds the runtime
permissions, so [`MainActivity.java`](../android/app/src/main/java/app/undepressable/MainActivity.java)
requests `CAMERA` + `RECORD_AUDIO` on launch. If you ever see a black stream on
a real device, check that these were granted (Settings → Apps → Undepressable →
Permissions). This is the one piece that still needs an on-device pass — see
[`TEST_PLAN.md`](TEST_PLAN.md) Scenario 1.

## Build a signed release APK (for self-distribution)

F-Droid signs its own builds, but for handing out an APK directly (or your own
repo) you sign it yourself. **Never commit the keystore or its passwords.**

1. Generate a keystore once (keep it safe and backed up — losing it means you
   can't ship updates under the same signature):

   ```bash
   keytool -genkey -v -keystore undepressable-release.jks \
     -keyalg RSA -keysize 2048 -validity 10000 -alias undepressable
   ```

2. Point Gradle at it **without hardcoding secrets** — put them in
   `~/.gradle/gradle.properties` (outside the repo):

   ```properties
   UNDEP_STORE_FILE=/absolute/path/undepressable-release.jks
   UNDEP_STORE_PASSWORD=…
   UNDEP_KEY_ALIAS=undepressable
   UNDEP_KEY_PASSWORD=…
   ```

3. Add a `signingConfigs` block to `android/app/build.gradle` reading those
   properties, and wire it into `buildTypes.release`:

   ```gradle
   signingConfigs {
       release {
           if (project.hasProperty('UNDEP_STORE_FILE')) {
               storeFile file(UNDEP_STORE_FILE)
               storePassword UNDEP_STORE_PASSWORD
               keyAlias UNDEP_KEY_ALIAS
               keyPassword UNDEP_KEY_PASSWORD
           }
       }
   }
   buildTypes {
       release {
           signingConfig signingConfigs.release
           minifyEnabled false
       }
   }
   ```

4. Build:

   ```bash
   npm run build && npx cap sync android
   cd android && ./gradlew assembleRelease
   # → android/app/build/outputs/apk/release/app-release.apk
   ```

## Versioning

Bump both fields in [`android/app/build.gradle`](../android/app/build.gradle)
for every release (`versionCode` must strictly increase — F-Droid uses it):

```gradle
versionCode 2
versionName "0.9.2"
```

Keep `versionName` in step with the web app's version so the in-app footer and
the store listing match.

## Publishing on F-Droid

Two routes:

### A) Submit to the main F-Droid catalogue

1. Push the source (including `android/`) to a public git repo with a FOSS
   license (e.g. AGPL/GPL/MIT). F-Droid builds **from source**, so the web
   assets must be built during the recipe, not shipped pre-built.
2. Fork [`fdroiddata`](https://gitlab.com/fdroid/fdroiddata) and add a metadata
   file `metadata/app.undepressable.yml`:

   ```yaml
   Categories:
     - Security
     - Multimedia
   License: AGPL-3.0-or-later
   SourceCode: https://github.com/marcuspuchalla/undepressable
   IssueTracker: https://github.com/marcuspuchalla/undepressable/issues

   AutoName: Undepressable
   Summary: Censorship-resistant P2P live streaming
   Description: |-
     Stream live from your phone to trusted people with no central server.
     Each viewer keeps their own signed copy, so no single takedown erases
     what happened.

   RepoType: git
   Repo: https://github.com/marcuspuchalla/undepressable.git

   Builds:
     - versionName: "1.0"
       versionCode: 1
       commit: v1.0
       subdir: p2p-stream/android/app
       sudo: []
       init: []
       prebuild:
         - pushd ../.. && npm ci && npm run build && npx cap sync android && popd
       gradle:
         - yes

   AutoUpdateMode: Version
   UpdateCheckMode: Tags
   CurrentVersion: "1.0"
   CurrentVersionCode: 1
   ```

   The `prebuild` step is the important part: it runs `npm ci && npm run build &&
   npx cap sync` so F-Droid reproduces the bundled web assets from source.
3. Test the recipe locally with `fdroid build -v app.undepressable`, then open a
   merge request against `fdroiddata`.

Note: F-Droid's build servers run `npm`, but heavy Node builds sometimes need
tuning (network access during `npm ci` is allowed at build time). If the review
flags the bundled `node_modules`/lockfile, keep `package-lock.json` committed so
the build is deterministic.

### B) Run your own F-Droid repo (fastest, no review queue)

Good for getting the app to activists now without waiting on upstream review.

```bash
pip install fdroidserver          # or: brew install fdroidserver
mkdir fdroid-repo && cd fdroid-repo
fdroid init
cp /path/app-release.apk repo/
fdroid update --create-metadata    # signs the index
```

Serve the `fdroid-repo` folder over HTTPS (or Tor/onion). Users add the repo URL
in the F-Droid client and get updates from there. Because the repo index is
signed with your key, updates are as tamper-evident as the main catalogue.

## Why this is resilient distribution

- APKs sideload with no account and no store — the hardest channel to block.
- A self-hosted (or onion) F-Droid repo means no gatekeeper can pull the app.
- The build has no Google dependencies, so it runs on de-Googled/GrapheneOS phones.

See [`MOBILE_DISTRIBUTION.md`](../MOBILE_DISTRIBUTION.md) for the wider sideloading
picture and [`FEASIBILITY.md`](FEASIBILITY.md) for how Android compares to iOS.
